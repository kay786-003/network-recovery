# 架構決策

## 記錄格式

決策採只追加記錄。每筆使用 `### D0001 — 標題`，並依序填寫「日期」、「狀態」、「背景」、「決定」、「影響」。日期使用 `YYYY-MM-DD`；狀態使用「採用」、「被取代」或「提議」。取代既有決策時新增一筆並互相連結，不刪除舊紀錄。

## 決策紀錄

### D0001 — Windows 原生單一 EXE

- 日期：2026-10-23
- 狀態：採用
- 背景：需要管理員權限、選擇網卡及 Windows Wi-Fi 連線設定。
- 決定：使用 C# 5、.NET Framework 4.8、Windows Forms 與 WLAN API，產出單一 EXE。
- 影響：保留既有 Windows 建置流程，不引入 .NET SDK、NuGet 或網頁介面依賴。

### D0002 — 密碼交由 Windows 儲存

- 日期：2026-10-23
- 狀態：採用
- 背景：背景監控需要重連 Wi-Fi，但專案與設定不應保存明文密碼。
- 決定：使用所有使用者可用的 Windows Wi-Fi 設定；密碼只在記憶體及 WLAN API 中處理。
- 影響：企業及僅限單一使用者的設定需要在 Windows 中先完成適當設定，不靜默覆寫。

### D0003 — 開機等待期間累計斷網

- 日期：2026-10-23
- 狀態：採用
- 背景：使用者要求重開後持續無網，滿 5 分鐘即再次修復，不能再額外等待 3 分鐘。
- 決定：以單調時間累計斷網，正式流程維持 180 秒修復、修復後 60 秒重啟、開機等待 300 秒；沒有重啟次數上限。
- 影響：開機等待與日常斷網計時分開判斷，保留持續斷網的恢復流程。

### D0004 — 固定文件登記與安全封裝

- 日期：2026-10-23
- 狀態：採用
- 背景：新 Agent session 需要相同的文件入口、目錄與狀態，不應建立多套規則或上傳舊私人紀錄。
- 決定：使用根目錄 `AGENTS.md` 與 `docs/documentation-schema.json` 作為固定規則及格式登記，CI 檢查；封裝採明確允許清單。
- 影響：新增／改名文件需同步更新登記與索引。`legacy/`、`work/`、`dist/` 不提交。

### D0005 — 首次設定前驗證外網連線

- 日期：2026-10-24
- 狀態：採用
- 背景：首次設定前若所有外網探測服務都無法連線，啟用後的監控會把這種網路環境當成斷網，可能反覆修復或重新啟動。
- 決定：尚無設定檔且未安裝監控工作時，先以既有三個外網服務執行一次探測；至少一個成功才開啟設定視窗，全部失敗時提示並以非零退出碼結束。預覽、`--monitor`／`--probe` 模式及已設定電腦不受此預檢阻擋。
- 影響：首次設定需要至少一個探測服務可達；若網路政策封鎖全部服務，使用者需先調整網路或防火牆。此預檢不取代斷網修復的實機驗收。

### D0006 — 明確的 DPI 設計基準與可捲動設定畫布

- 日期：2026-10-24
- 狀態：採用
- 背景：跨電腦執行時，高 DPI 導致固定座標與字體縮放不一致，文字遭裁切；完整設定畫面可能超出小螢幕。
- 決定：保留 WinForms 與既有版面，明確設定 96 DPI 基準並暫停配置至控制項建立完成；縮放後畫布保持最小尺寸，由外層視窗提供雙向捲動。
- 影響：較小螢幕需要捲動到啟用按鈕；不改變監控、權限、安裝路徑或排程名稱。

### D0007 — 重啟次數上限與冷卻窗

- 日期：2026-10-28
- 狀態：採用（取代 D0003 中「沒有重啟次數上限」的部分，180／60／300 秒維持不變）
- 背景：使用者在外工作時透過 VPN 連回公司電腦，連線卡死等於無法工作，因此寧可誤判並重新啟動，也不要長時間無法連線；但目標網路長時間不存在時，無限制重啟只會造成無效的連續重新啟動。
- 決定：維持持續斷網 180 秒修復網卡、修復後 60 秒仍無外網才重新啟動、開機等待 300 秒。新增上限：連續 4 小時內最多重新啟動 5 次，採滾動時間窗；達到上限後不再重新啟動，只繼續修復網卡與重新連線，直到恢復或時間窗屆滿後重新取得額度。歸零條件：必須是外部檢查服務實際有回應才算恢復，該次成功即把次數歸零，並從恢復時刻重新起算 4 小時。單純連上 Wi-Fi、取得區網位址，或 Wi-Fi 圖示顯示已連線，都不算恢復，不歸零。
- 影響：README、AGENTS 與 ROADMAP 需同步這個上限與歸零條件；`RecoveryEngine.cs` 需加入以單調時間計算的計數（尚未實作）；需新增上限、歸零與冷卻的純資料測試，且測試必須涵蓋「Wi-Fi 已連線但探測失敗時不歸零」；此上限屬正式預設，未經使用者要求不得再改動。

### D0008 — 目標 SSID 不在時的行為與已儲存 SSID 自動重試

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：目前設定只有一個 Wi-Fi。設定的 SSID 不在範圍內時，重啟網卡或電腦都不會讓它出現，會形成無效重啟；使用者外出時無法到場處理。使用者另外要求程式能重試其他已儲存密碼的 Wi-Fi。
- 決定：分兩部分。(1) 以掃描結果判別原因：看得到其他 SSID 但看不到目標，視為目標不在範圍，不消耗 D0007 的重啟次數，改為持續掃描等待，目標回來即自動連線；一個 SSID 都看不到，視為網卡或驅動異常，照原有修復與重啟流程處理。(2) 新增自動重連重試：依序嘗試其他在 Windows 已儲存、掃描得到的 SSID，成功連上即視為連線恢復並歸零重啟計數；密碼仍由 Windows 保管，只在記憶體與 WLAN API 中處理。
- 影響：設定格式仍只記錄一個主要 Wi-Fi，重試候選來自 Windows 已儲存設定，不新增密碼欄位、不寫入其他 SSID 的憑證；需先更新 `docs/ARCHITECTURE.md` 與 README，再改程式並補實機驗收。

### D0009 — 不做分層外網探測，維持單一可用性判定

- 日期：2026-10-28
- 狀態：採用
- 背景：曾評估以 DNS、TCP、HTTP 分層並增加多個探測端點，用來區分網卡故障與上游或 VPN 故障，減少誤判重啟。
- 決定：不實作分層探測。維持「任一個外部檢查服務有回應即視為可以上網」，無法上網就進入既有修復與重啟流程。理由：使用者的主要用途是遠端連回公司電腦，寧可錯判後重新啟動，也不要因判定過於保守而長時間連不上。
- 影響：`docs/ISSUES.md` 的 ISSUE-001 調整為記錄而不處理；外網判定、探測服務數量與逾時維持現狀；不新增逐端點診斷或可自訂端點設定。

### D0010 — 以關閉睡眠與休眠為使用前提

- 日期：2026-10-28
- 狀態：採用
- 背景：使用者的電腦不會進入睡眠或休眠，且不要求驗證跨睡眠、休眠或系統時間被調整時的計時行為。
- 決定：把「關閉睡眠與休眠」列為 README 的使用前提，不實作也不列入驗收跨睡眠／休眠的計時。
- 影響：睡眠或休眠期間監控不會執行，屬已接受的行為；若日後要支援，須另立決策並補計時與喚醒後的驗收。

### D0011 — 重新啟動只保留簡易紀錄

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：曾評估一鍵匯出去識別化診斷包與事件時間軸。使用者只需要知道程式是否重新啟動過以及原因。
- 決定：每次重新啟動前寫入一筆含時間與原因的紀錄，例如「修復後 60 秒仍無外網」或「已達 4 小時重啟上限，改為修復網卡」，不建立診斷包、逐端點結果或事件時間軸匯出。紀錄必須在觸發重新啟動前完成寫入，確保重啟後查得到。
- 影響：`events.log` 維持精簡；寫入失敗時的行為需明確定義，且不得因為寫入失敗而略過既有的安全檢查。

### D0012 — 系統匣圖示與暫時暫停監控

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：使用者需要臨時停止自動修復（例如自己正在處理網路、或短暫異常時不希望被重新啟動），並希望能從 Windows 系統匣直接操作，不必每次開啟設定視窗。
- 決定：新增系統匣圖示，提供右鍵選單的暫停監控 1、2、4、24 小時，以及取消暫停、立即修復、開啟設定、停止監控；圖示需能反映目前狀態（正常、已暫停、修復中）。暫停期間不修復網卡、不重新啟動，但仍持續記錄外網探測結果；到期自動恢復，並重新起算 180 秒／60 秒與 D0007 的 4 小時重啟窗。
- 影響：背景監控以 SYSTEM 工作排程執行，系統匣圖示只在使用者登入時存在，因此暫停狀態必須寫入 ProgramData 的狀態檔供 `--monitor` 讀取，不能只存在圖示程序中；需新增使用者 session 的啟動方式與 `--tray` 模式，且不得改動既有 `--monitor`、排程名稱或 ProgramData 路徑；暫停與恢復狀態也要能在設定視窗中看到。

### D0013 — 一鍵修復網路異常（先保存參考腳本）

- 日期：2026-10-28
- 狀態：採用（尚未實作；腳本保存在 `docs/reference/reset-network.cmd`）
- 背景：使用者提供一份手動修復腳本（關閉目前使用者的 proxy、重設 WinHTTP proxy、清除 DNS 快取、重設 Winsock 與 TCP/IP），希望在程式中提供一鍵修復，讓使用者不必自行開命令提示字元。本次只保存腳本，不改程式。
- 決定：先把腳本保持原樣保存為參考資產，功能整合留待後續授權。整合時必須遵守：只能由使用者明確點選執行，不得自動或由排程觸發；依風險分階段執行（先清除 DNS 快取與重連網卡，再處理 Winsock／TCP/IP 重設）；重設 Winsock 或 TCP/IP 需要重新啟動才生效，交由既有的重啟路徑處理，不額外重啟；執行前後各寫一筆紀錄。
- 影響：腳本以 `HKCU` 修改 proxy，但背景監控以 SYSTEM 執行時 `HKCU` 是 SYSTEM 帳戶，整合時必須改用目前登入使用者的 SID（`HKEY_USERS`）或在使用者 session 中執行，否則會改錯設定；刪除 `ProxyServer`／`AutoConfigURL` 與重設 TCP/IP 可能影響固定 IP、自訂路由、VPN 虛擬網卡及公司代理設定，整合前必須先備份可還原的設定並取得使用者確認；此功能不得取代既有的自動修復流程，未具備還原機制前不得設為預設動作。

### D0014 — D0007 的持久化重啟額度

- 日期：2026-10-28
- 狀態：採用
- 背景：D0007 本次獲授權實作；僅在記憶體計數會在每次重啟後失效，且單調時鐘無法跨 Windows 重啟延續。
- 決定：以受保護的 `restart-history.xml` 原子保存最多五筆預約的年齡、開機識別與 UTC 保存時間；先持久化再要求重啟，失敗或中斷的要求仍計次。同次開機以 uptime 計時，僅跨開機以 UTC 差值銜接（倒退取零），不混用本地時間。達上限仍按 180／60 秒循環修復；外網探測成功清零。檔案損壞視為剛用完五次，保存失敗不重啟；沿用 ACL 與連結防護，安裝不清除額度。
- 影響：D0007 已實作於未發行建置，純資料測試覆蓋滾動邊界、外網歸零、跨程序／開機及損壞狀態。跨開機 UTC 大幅前進可能提前釋放額度，無可信跨開機單調時源時無法消除此限制；睡眠仍依 D0010 排除。D0011 的保證紀錄寫入及 D0008 不在本次範圍。

### D0015 — D0008～D0013 的整合與舊版交接

- 日期：2026-10-28
- 狀態：採用
- 背景：使用者擴大授權，要求完成 D0007～D0014 並確認舊監控交接。D0009／D0010 維持既有行為；D0014 的本機持久化延用。
- 決定：整合可見 SSID 判別及 Windows 已儲存 profile 輪流重試；D0008 的恢復定義以 D0007 的外網成功為準。新增 D0011 的持久化紀錄閘門，D0012 的本機暫停狀態及互動系統匣排程，D0013 的基本／進階手動修復、私有備份與失敗還原。進階重設前須由使用者點選確認，禁止背景自動執行。監控、安裝、暫停與手動修復共用操作鎖；修復只重設斷網觀察，取消／到期暫停依 D0012 重設額度。
- 影響：D0007～D0014 已於未發行建置整合，原決策中的「尚未實作」保留為歷史。新增 `NetworkRecovery Tray`，原 `NetworkRecovery Monitor` 名稱及安裝路徑不變。升級停用舊 monitor／tray、替換檔案，再交接 legacy；失敗還原快照，不刪除任意舊腳本。舊版未保存的重啟次數無法補算。實際升級、登入系統匣、SSID 掃描、暫停及進階修復／還原仍需當次實機授權與驗收。

### D0016 — 系統匣暫停勾選與四項監控工具

- 日期：2026-10-28
- 狀態：採用（依使用者要求，調整 D0012 的取消操作及取代 D0013／D0015 的手動重啟入口）
- 背景：使用者要求暫停僅在系統匣右鍵操作，工具視窗簡化為四個按鈕，修復後不代為重新啟動。
- 決定：右鍵提供 1／2／4／24 小時，當前選項打勾，再點同一項取消；點其他時長重新起算，到期取消勾選。工具只保留「備份」、「還原備份」、「一鍵修復並重設」、「移除備份」。獨立備份不覆寫既有資料；修復前驗證已有備份或先建立新備份。修復／還原成功後只顯示需自行重啟的提醒，按確定關閉，不要求 shutdown。
- 影響：移除工具視窗的暫停、停止及重啟入口，不新增獨立取消暫停選單項。暫停仍以本機狀態檔及操作鎖控制，避免只改 UI 勾選卻未保存；既有自動斷網監控與 D0007 上限維持不變。

### D0017 — 安裝路徑以必要權限更新已驗證物件

- 日期：2026-11-06
- 狀態：採用
- 背景：使用者回報「無法保護安裝路徑」。舊訊息沒有 Windows 錯誤碼，無法確認截圖當次根因；隔離測試重現 MAXIMUM_ALLOWED 會因包含 DELETE，與現有不分享 delete 的目錄讀取控制代碼衝突（Windows 錯誤 32）。單純把共用模式放寬會削弱防替換保護，改用 SetSecurityInfo 的自動傳播也可能影響既有私人備份及不可信子項。
- 決定：開啟目標時只要求 READ_CONTROL、WRITE_DAC、WRITE_OWNER、FILE_READ_ATTRIBUTES。維持不跟隨重新解析點、不分享 delete，並驗證同一控制代碼的類型及硬連結數。使用 Windows 內建 NtSetSecurityObject 僅更新該物件的 owner／受保護 DACL，保留原有管理員／SYSTEM 寫入及私人備份政策，不遍歷既有子項。錯誤保留 Windows 代碼與系統說明，不忽略權限失敗。
- 影響：新增 ntdll 內建 API 呼叫，不增加執行期套件；以可由非提升權限帳戶執行的隔離檔案測試驗證共用衝突、ACL 保護、既有子項不變、新檔繼承、硬連結與 junction 拒絕。測試使用目前帳戶作為測試物件 owner；正式安裝仍指定 Administrators。實際 Program Files／ProgramData 的管理員安裝與舊排程交接仍待實機驗收。

### D0018 — 系統匣雙擊開啟主設定視窗

### D0019 — 主設定視窗單一執行個體

- 日期：2026-11-06
- 狀態：採用
- 背景：使用者回報重複雙擊系統匣圖示會開啟多個 EXE 主視窗。
- 決定：在同一登入 session／使用者範圍以固定命名 Mutex 保留一個主設定程序，其他啟動透過命名事件通知原視窗還原並請求前景焦點。系統匣先通知既有程序，啟動期間合併重複點擊；主視窗鎖在外網預檢前取得，避免次要程序重跑初始化。
- 影響：主視窗關閉後可重新開啟；預覽、監控及系統匣模式不受此鎖影響。命名不隨 EXE 檔名或版本改變，升級前須關閉既有設定視窗；不強制終止舊版本已開啟的視窗。Windows 前景限制仍由作業系統決定，不繞過其他桌面或使用者的權限。

### D0021 — 可選的外網地區程序保護

- 日期：2026-11-13
- 狀態：採用
- 背景：使用者提供每 120 秒查詢 ipwho.is 並在 CN／MO／HK 結束 claude 與 cowork-svc 的腳本，要求整合及發布新版。
- 決定：新增預設為 false 的設定與勾選框，只有儲存並啟用後由既有 SYSTEM 監控執行。查詢使用 TLS 1.2、10 秒逾時、32 KiB 回應上限，拒絕重新導向；必須 success 為布林 true 且 country_code 為兩位大寫字母。只有 CN／MO／HK 可觸發固定程序允許清單，包含其他登入 session 的同名程序；各程序終止失敗不阻止其餘程序。查詢完成後以單調時間等待 120 秒再查詢。
- 影響：地區查詢在獨立非同步工作執行，結果由持有既有操作鎖的監控迴圈消費；不加入 D0009 的可用性判定、不更動修復或重啟額度。暫停或控制狀態讀取失敗時丟棄在途結果，不發出新查詢或終止程序。沿用既有啟用、停止、安裝還原與 ACL，舊設定缺少欄位時不啟用。使用 Framework 內建 System.Web.Extensions JSON 解析，不增加 NuGet 或額外部署檔。日誌只存國家代碼、固定程序名及結果，不存 IP、完整回應或私人診斷。SYSTEM 的外網出口／Proxy 可能與互動應用或分流 VPN 不同，地區結果不保證代表 Claude 的實際出口；此功能不防止使用者重新開啟程序。

### D0022 — 跟隨系統配色的 Fluent 介面與程式繪製圖標

- 日期：2026-11-13
- 狀態：採用
- 背景：使用者認為深藍底、青色強調的介面與 AI 生成的盾牌圖標不好看，要求重新設計介面、圖標、選單與顏色，並選擇配色跟隨 Windows 淺色／深色設定。
- 決定：`Theme.cs` 提供淺色與深色兩套調色盤，視窗開啟時依 HKCU `AppsUseLightTheme` 唯讀選擇，高對比模式改用淺色；深色時以 DWM 與 `DarkMode_Explorer` 讓標題列及捲軸變暗。按鈕、核取方塊、輸入框外框、下拉選單、清單、流程步驟與系統匣選單均自繪，圖示字形取自 Windows 內建 Segoe MDL2 Assets。圖標改由 `src/IconArt.cs` 向量繪製，`build-icons.ps1` 以 Add-Type 載入同一檔案逐尺寸產生 ICO，取代 D0020 的 PNG 原圖轉檔；系統匣 24 像素以下使用無徽章的簡化圖形。

### D0023 — 地區程序保護改為使用者以名稱選擇程序

- 日期：2026-11-13
- 狀態：採用（修訂 D0021 的固定程序清單）
- 背景：使用者要求地區程序保護觸發時可自由選擇要結束的程序，並從即時程序清單（工作管理員「詳細資料」）挑選；因 Windows 應用更新可能改變安裝路徑，只以程序名稱記錄與比對，不記錄路徑。
- 決定：`AppConfig` 新增 `GuardProcessNames` 字串陣列，只存去除 `.exe` 的程序名稱；欄位缺少（null）時沿用 D0021 的 claude／cowork-svc，空陣列表示未選擇並阻止儲存。設定視窗以「選擇程序」開啟即時清單，依名稱分組顯示數量與描述，每 3 秒更新；描述讀自模組版本資訊，路徑不保存。名稱在選擇、監控載入設定及結束前都會正規化並驗證，拒絕路徑、萬用字元及無效字元，上限 64 個；Windows 核心程序（System、csrss、lsass、svchost、winlogon、dwm 等）與 NetworkRecovery 本身永遠排除，防止誤選或設定檔被竄改導致系統當機。
- 影響：同名程序（不論路徑）都會被結束，使用者須自行判斷名稱是否過於通用；保護清單只是最低安全網，未列出的其他系統程序仍可能被選擇。其他 D0021 行為（查詢間隔、地區判定、暫停丟棄、日誌不含 IP）不變；日誌改為記錄使用者選擇的程序名稱。未新增相依套件，仍為單一 EXE。
