# 架構決策

## 記錄格式

決策採只追加記錄。每筆使用 `### D0001 — 標題`，並依序填寫「日期」、「狀態」、「背景」、「決定」、「影響」。日期使用 `YYYY-MM-DD`；狀態使用「採用」、「被取代」或「提議」。取代既有決策時新增一筆並互相連結，不刪除舊紀錄。

## 決策紀錄

### D0001 — Windows 原生單一 EXE

- 日期：2026-10-23
- 狀態：採用
- 背景：需要管理員權限、選擇網卡及 Windows Wi-Fi 連線設定。
- 決定：使用 C# 5、.NET Framework 4.8、Windows Forms 與 WLAN API，產出單一 EXE。
- 影響：保留既有 Windows 建置流程，不引入 .NET SDK、NuGet 或網頁介面依賴。

### D0002 — 密碼交由 Windows 儲存

- 日期：2026-10-23
- 狀態：採用
- 背景：背景監控需要重連 Wi-Fi，但專案與設定不應保存明文密碼。
- 決定：使用所有使用者可用的 Windows Wi-Fi 設定；密碼只在記憶體及 WLAN API 中處理。
- 影響：企業及僅限單一使用者的設定需要在 Windows 中先完成適當設定，不靜默覆寫。

### D0003 — 開機等待期間累計斷網

- 日期：2026-10-23
- 狀態：採用
- 背景：使用者要求重開後持續無網，滿 5 分鐘即再次修復，不能再額外等待 3 分鐘。
- 決定：以單調時間累計斷網，正式流程維持 180 秒修復、修復後 60 秒重啟、開機等待 300 秒；沒有重啟次數上限。
- 影響：開機等待與日常斷網計時分開判斷，保留持續斷網的恢復流程。

### D0004 — 固定文件登記與安全封裝

- 日期：2026-10-23
- 狀態：採用
- 背景：新 Agent session 需要相同的文件入口、目錄與狀態，不應建立多套規則或上傳舊私人紀錄。
- 決定：使用根目錄 `AGENTS.md` 與 `docs/documentation-schema.json` 作為固定規則及格式登記，CI 檢查；封裝採明確允許清單。
- 影響：新增／改名文件需同步更新登記與索引。`legacy/`、`work/`、`dist/` 不提交。

### D0005 — 首次設定前驗證外網連線

- 日期：2026-10-24
- 狀態：採用
- 背景：首次設定前若所有外網探測服務都無法連線，啟用後的監控會把這種網路環境當成斷網，可能反覆修復或重新啟動。
- 決定：尚無設定檔且未安裝監控工作時，先以既有三個外網服務執行一次探測；至少一個成功才開啟設定視窗，全部失敗時提示並以非零退出碼結束。預覽、`--monitor`／`--probe` 模式及已設定電腦不受此預檢阻擋。
- 影響：首次設定需要至少一個探測服務可達；若網路政策封鎖全部服務，使用者需先調整網路或防火牆。此預檢不取代斷網修復的實機驗收。
