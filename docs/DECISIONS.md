# 架構決策

## 記錄格式

決策採只追加記錄。每筆使用 `### D0001 — 標題`，並依序填寫「日期」、「狀態」、「背景」、「決定」、「影響」。日期使用 `YYYY-MM-DD`；狀態使用「採用」、「被取代」或「提議」。取代既有決策時新增一筆並互相連結，不刪除舊紀錄。

## 決策紀錄

### D0001 — Windows 原生單一 EXE

- 日期：2026-10-23
- 狀態：採用
- 背景：需要管理員權限、選擇網卡及 Windows Wi-Fi 連線設定。
- 決定：使用 C# 5、.NET Framework 4.8、Windows Forms 與 WLAN API，產出單一 EXE。
- 影響：保留既有 Windows 建置流程，不引入 .NET SDK、NuGet 或網頁介面依賴。

### D0002 — 密碼交由 Windows 儲存

- 日期：2026-10-23
- 狀態：採用
- 背景：背景監控需要重連 Wi-Fi，但專案與設定不應保存明文密碼。
- 決定：使用所有使用者可用的 Windows Wi-Fi 設定；密碼只在記憶體及 WLAN API 中處理。
- 影響：企業及僅限單一使用者的設定需要在 Windows 中先完成適當設定，不靜默覆寫。

### D0003 — 開機等待期間累計斷網

- 日期：2026-10-23
- 狀態：採用
- 背景：使用者要求重開後持續無網，滿 5 分鐘即再次修復，不能再額外等待 3 分鐘。
- 決定：以單調時間累計斷網，正式流程維持 180 秒修復、修復後 60 秒重啟、開機等待 300 秒；沒有重啟次數上限。
- 影響：開機等待與日常斷網計時分開判斷，保留持續斷網的恢復流程。

### D0004 — 固定文件登記與安全封裝

- 日期：2026-10-23
- 狀態：採用
- 背景：新 Agent session 需要相同的文件入口、目錄與狀態，不應建立多套規則或上傳舊私人紀錄。
- 決定：使用根目錄 `AGENTS.md` 與 `docs/documentation-schema.json` 作為固定規則及格式登記，CI 檢查；封裝採明確允許清單。
- 影響：新增／改名文件需同步更新登記與索引。`legacy/`、`work/`、`dist/` 不提交。

### D0005 — 首次設定前驗證外網連線

- 日期：2026-10-24
- 狀態：採用
- 背景：首次設定前若所有外網探測服務都無法連線，啟用後的監控會把這種網路環境當成斷網，可能反覆修復或重新啟動。
- 決定：尚無設定檔且未安裝監控工作時，先以既有三個外網服務執行一次探測；至少一個成功才開啟設定視窗，全部失敗時提示並以非零退出碼結束。預覽、`--monitor`／`--probe` 模式及已設定電腦不受此預檢阻擋。
- 影響：首次設定需要至少一個探測服務可達；若網路政策封鎖全部服務，使用者需先調整網路或防火牆。此預檢不取代斷網修復的實機驗收。

### D0006 — 明確的 DPI 設計基準與可捲動設定畫布

- 日期：2026-10-24
- 狀態：採用
- 背景：跨電腦執行時，高 DPI 導致固定座標與字體縮放不一致，文字遭裁切；完整設定畫面可能超出小螢幕。
- 決定：保留 WinForms 與既有版面，明確設定 96 DPI 基準並暫停配置至控制項建立完成；縮放後畫布保持最小尺寸，由外層視窗提供雙向捲動。
- 影響：較小螢幕需要捲動到啟用按鈕；不改變監控、權限、安裝路徑或排程名稱。

### D0007 — 重啟次數上限與冷卻窗

- 日期：2026-10-28
- 狀態：採用（取代 D0003 中「沒有重啟次數上限」的部分，180／60／300 秒維持不變）
- 背景：使用者在外工作時透過 VPN 連回公司電腦，連線卡死等於無法工作，因此寧可誤判並重新啟動，也不要長時間無法連線；但目標網路長時間不存在時，無限制重啟只會造成無效的連續重新啟動。
- 決定：維持持續斷網 180 秒修復網卡、修復後 60 秒仍無外網才重新啟動、開機等待 300 秒。新增上限：連續 4 小時內最多重新啟動 5 次；任一次外網探測成功即把次數歸零，並從恢復時刻重新起算 4 小時。達到上限後不再重新啟動，只繼續修復網卡與重新連線，直到連線恢復或 4 小時窗屆滿後重新取得額度。
- 影響：README、AGENTS 與 ROADMAP 需同步這個上限；`RecoveryEngine.cs` 需加入以單調時間計算的計數（尚未實作）；需新增上限、歸零與冷卻的純資料測試；此上限屬正式預設，未經使用者要求不得再改動。

### D0008 — 目標 SSID 不在時的行為與已儲存 SSID 自動重試

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：目前設定只有一個 Wi-Fi。設定的 SSID 不在範圍內時，重啟網卡或電腦都不會讓它出現，會形成無效重啟；使用者外出時無法到場處理。使用者另外要求程式能重試其他已儲存密碼的 Wi-Fi。
- 決定：分兩部分。(1) 以掃描結果判別原因：看得到其他 SSID 但看不到目標，視為目標不在範圍，不消耗 D0007 的重啟次數，改為持續掃描等待，目標回來即自動連線；一個 SSID 都看不到，視為網卡或驅動異常，照原有修復與重啟流程處理。(2) 新增自動重連重試：依序嘗試其他在 Windows 已儲存、掃描得到的 SSID，成功連上即視為連線恢復並歸零重啟計數；密碼仍由 Windows 保管，只在記憶體與 WLAN API 中處理。
- 影響：設定格式仍只記錄一個主要 Wi-Fi，重試候選來自 Windows 已儲存設定，不新增密碼欄位、不寫入其他 SSID 的憑證；需先更新 `docs/ARCHITECTURE.md` 與 README，再改程式並補實機驗收。

### D0009 — 不做分層外網探測，維持單一可用性判定

- 日期：2026-10-28
- 狀態：採用
- 背景：曾評估以 DNS、TCP、HTTP 分層並增加多個探測端點，用來區分網卡故障與上游或 VPN 故障，減少誤判重啟。
- 決定：不實作分層探測。維持「任一個外部檢查服務有回應即視為可以上網」，無法上網就進入既有修復與重啟流程。理由：使用者的主要用途是遠端連回公司電腦，寧可錯判後重新啟動，也不要因判定過於保守而長時間連不上。
- 影響：`docs/ISSUES.md` 的 ISSUE-001 調整為記錄而不處理；外網判定、探測服務數量與逾時維持現狀；不新增逐端點診斷或可自訂端點設定。

### D0010 — 以關閉睡眠與休眠為使用前提

- 日期：2026-10-28
- 狀態：採用
- 背景：使用者的電腦不會進入睡眠或休眠，且不要求驗證跨睡眠、休眠或系統時間被調整時的計時行為。
- 決定：把「關閉睡眠與休眠」列為 README 的使用前提，不實作也不列入驗收跨睡眠／休眠的計時。
- 影響：睡眠或休眠期間監控不會執行，屬已接受的行為；若日後要支援，須另立決策並補計時與喚醒後的驗收。

### D0011 — 重新啟動只保留簡易紀錄

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：曾評估一鍵匯出去識別化診斷包與事件時間軸。使用者只需要知道程式是否重新啟動過以及原因。
- 決定：每次重新啟動前寫入一筆含時間與原因的紀錄，例如「修復後 60 秒仍無外網」或「已達 4 小時重啟上限，改為修復網卡」，不建立診斷包、逐端點結果或事件時間軸匯出。紀錄必須在觸發重新啟動前完成寫入，確保重啟後查得到。
- 影響：`events.log` 維持精簡；寫入失敗時的行為需明確定義，且不得因為寫入失敗而略過既有的安全檢查。

### D0012 — 系統匣圖示與暫時暫停監控

- 日期：2026-10-28
- 狀態：採用（尚未實作）
- 背景：使用者需要臨時停止自動修復（例如自己正在處理網路、或短暫異常時不希望被重新啟動），並希望能從 Windows 系統匣直接操作，不必每次開啟設定視窗。
- 決定：新增系統匣圖示，提供右鍵選單的暫停監控 1、2、4、24 小時，以及取消暫停、立即修復、開啟設定、停止監控；圖示需能反映目前狀態（正常、已暫停、修復中）。暫停期間不修復網卡、不重新啟動，但仍持續記錄外網探測結果；到期自動恢復，並重新起算 180 秒／60 秒與 D0007 的 4 小時重啟窗。
- 影響：背景監控以 SYSTEM 工作排程執行，系統匣圖示只在使用者登入時存在，因此暫停狀態必須寫入 ProgramData 的狀態檔供 `--monitor` 讀取，不能只存在圖示程序中；需新增使用者 session 的啟動方式與 `--tray` 模式，且不得改動既有 `--monitor`、排程名稱或 ProgramData 路徑；暫停與恢復狀態也要能在設定視窗中看到。

### D0013 — 一鍵修復網路異常（先保存參考腳本）

- 日期：2026-10-28
- 狀態：採用（尚未實作；腳本保存在 `docs/reference/reset-network.cmd`）
- 背景：使用者提供一份手動修復腳本（關閉目前使用者的 proxy、重設 WinHTTP proxy、清除 DNS 快取、重設 Winsock 與 TCP/IP），希望在程式中提供一鍵修復，讓使用者不必自行開命令提示字元。本次只保存腳本，不改程式。
- 決定：先把腳本保持原樣保存為參考資產，功能整合留待後續授權。整合時必須遵守：只能由使用者明確點選執行，不得自動或由排程觸發；依風險分階段執行（先清除 DNS 快取與重連網卡，再處理 Winsock／TCP/IP 重設）；重設 Winsock 或 TCP/IP 需要重新啟動才生效，交由既有的重啟路徑處理，不額外重啟；執行前後各寫一筆紀錄。
- 影響：腳本以 `HKCU` 修改 proxy，但背景監控以 SYSTEM 執行時 `HKCU` 是 SYSTEM 帳戶，整合時必須改用目前登入使用者的 SID（`HKEY_USERS`）或在使用者 session 中執行，否則會改錯設定；刪除 `ProxyServer`／`AutoConfigURL` 與重設 TCP/IP 可能影響固定 IP、自訂路由、VPN 虛擬網卡及公司代理設定，整合前必須先備份可還原的設定並取得使用者確認；此功能不得取代既有的自動修復流程，未具備還原機制前不得設為預設動作。
