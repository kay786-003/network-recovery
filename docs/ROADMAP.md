# 開發路線圖

## 目前狀態

目前為第一階段，GitHub 預發行版本 `v0.1.1`、EXE 產品版本 `0.1.1`／檔案版本 `0.1.1.0`。已具備設定介面、單網卡／單 Wi-Fi、自動連線及背景監控。使用者於 2026-10-28 回報新版 EXE 實機斷網修復與重新啟動電腦成功，但真實密碼寫入、開機後觸發路徑、安裝還原與升級覆蓋仍未驗收，因此不標示為穩定版本。路線圖只描述方向，不授權 Agent 自動開工。

## 第一階段

- [x] 管理員權限的單一 Windows EXE。
- [x] 列出網卡並選擇一張要修復的網卡。
- [x] 選擇一個 Wi-Fi，缺少已存設定時要求密碼並設定自動連線。
- [x] 儲存、啟用與停止背景監控。
- [x] 固定 180 秒／60 秒／300 秒的正式流程。
- [x] 建置、格式、密碼／XML 及只讀實機檢查。
- [x] 實機斷網修復與重新啟動電腦（使用者 2026-10-28 回報成功）。
- [ ] 真實密碼寫入、開機後 300 秒觸發路徑、安裝失敗還原與舊版覆蓋升級的驗收。

## 第二階段

- [ ] 多個 Wi-Fi 及明確的重連優先順序。
- [x] 找不到目標 SSID 時依掃描結果判別原因，並依序嘗試其他已儲存密碼的 SSID（D0008；未發行建置，待實機驗收）。
- [x] 目標 SSID 不在範圍時不消耗重啟次數，改為持續掃描等待（D0008）。
- [x] 連續 4 小時內最多重新啟動 5 次，外網探測成功即歸零（D0007）；未發行建置已完成，跨重啟實機驗收待辦。
- [x] 重新啟動前寫入含時間與原因的簡易紀錄，寫入失敗不重啟（D0011）。
- [ ] 介面可設定多久斷網後修復網卡。
- [ ] 介面可設定修復後多久仍未恢復才重啟。
- [ ] 介面可設定重開機後多久再次進入修復／重啟流程。
- [ ] 設定遷移與上述時間、順序、重試與上限的回歸測試。

## 第三階段

- [x] 系統匣圖示與狀態顯示：正常、已暫停、修復中（D0012；未發行建置）。
- [x] 從系統匣右鍵勾選暫停監控 1、2、4、24 小時，再點同一項取消，到期自動恢復（D0012、D0016）。
- [x] 監控工具四個按鈕：備份、還原備份、一鍵修復並重設、移除備份；修復後僅提醒自行重啟，並提供備份還原（D0013；不同 VPN／驅動及還原效果仍待實機驗收）。
- [x] 暫停狀態的保存、跨登出保留，以及隔離的策略回歸測試。
- [ ] 系統匣登入啟動、實際暫停／恢復、進階修復／還原及升級交接的實機驗收。

## 開始下一項工作的條件

依使用者當次指示選擇範圍。實機測試先確認當次操作授權；第二階段實作前先釐清多 Wi-Fi 與時間設定的驗收條件，更新架構決策後再改程式。不要因為清單未勾選就自行新增功能、發行版本或部署。
